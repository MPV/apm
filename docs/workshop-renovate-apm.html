The Problem

You solved dependency management for code. Agent configuration has no equivalent.

Without a package managerWith APM
Each dev configures agents manuallyapm install sets up everything
Instructions drift across machinesapm.lock.yaml pins exact versions
No way to share or reuse promptsPublish and install from any git host
MCP servers configured per-developerDeclared in manifest, installed consistently
Onboarding requires tribal knowledgeClone, apm install, done
No audit trail for agent configLock file tracks every dependency
The cost compounds with team size. 5 devs = 5 divergent agent configs. 50 devs = 50.

What is APM?

Think package.json — but for AI agent configuration
  • By Microsoft, open-source, ~2k GitHub stars
  • Language-agnostic: manages instructions, skills, prompts, agents, hooks, plugins, MCP servers
  • Git-native: packages are ordinary git repos — no central registry required
  • Manifest: apm.yml  |  Lock file: apm.lock.yaml
  • Multi-runtime: compiles for Copilot, Claude Code, Cursor, OpenCode, Codex from one file
pip install apm-cli        # install
apm init                   # create apm.yml
apm install                # resolve + lock + deploy

The Manifest: apm.yml

name: my-project
version: 1.0.0
description: AI-native web application
author: Contoso
license: MIT

dependencies:
  apm:
    # GitHub shorthand (implicit host)
    - microsoft/apm-sample-package#v1.0.0
    # Explicit non-GitHub host
    - gitlab.com/acme/security-rules#v1.0.0
    # Object form (subdirectory + alias)
    - git: https://gitlab.com/acme/repo.git
      path: instructions/security
      ref: v2.0
      alias: acme-sec
  mcp:
    - io.github.github/github-mcp-server

devDependencies:
  apm:
    - contoso/test-helpers#v1.0.0
#v1.0.0 — version pin (git tag)
gitlab.com/... — host encoded in string
Object form — for subdirectories, aliases, non-standard URLs
devDependencies — excluded from apm pack bundles
mcp: — MCP server declarations (separate concern)
For Renovate: focus on dependencies.apm and devDependencies.apm entries with version tags.

The Lock File: apm.lock.yaml

lockfile_version: "1"
generated_at: "2026-04-23T14:00:00Z"

dependencies:
  - repo_url: microsoft/apm-sample-package
    resolved_commit: a1b2c3d4e5f67890...
    resolved_ref: v1.0.0
    version: "1.0.0"
    depth: 1
    package_type: apm_package
    content_hash: "sha256:9f86d081884c..."
    deployed_files:
      - .github/agents/architect.agent.md
      - .github/skills/code-review/SKILL.md

  - repo_url: microsoft/common-prompts
    resolved_commit: f6e5d4c3b2a10987...
    resolved_ref: v2.0.0
    version: "2.0.0"
    depth: 2
    resolved_by: microsoft/apm-sample-package
    content_hash: "sha256:e3b0c44298fc..."
    deployed_files:
      - .github/instructions/common.md
resolved_commit — exact SHA (immutable pin)
depth: 2 + resolved_by — transitive dependency
content_hash — SHA-256 integrity verification
deployed_files — every file APM placed in your project
Commit to version control. git log apm.lock.yaml is your audit trail.

Lookup & Versioning

Datasource: github-tags or git-tags
Versioning: Semver — tags prefixed with v
No range constraints. Every dep is an exact pin.
No ^1.0.0, no ~1.x. Just #v1.0.0.

Tags on microsoft/apm-sample-package:

v1.0.0 —— v1.0.1 —— v1.1.0 —— v2.0.0
▲ pinned                                     ▲ Renovate proposes
EcosystemVersion sourceRanges?What Renovate updates
npmnpm RegistryYes (^, ~)package.json constraint
pipPyPIYes (>=, ==)requirements.txt
GoModule proxyYes (module)go.mod
APMGit tagsNo (exact pin)#ref in apm.yml

What's Next

Now
APM dependencies (dependencies.apm) with semver tags — full Renovate support.
Lock file artifact updates via apm install.
Near-term
MCP server versioning — as the MCP ecosystem matures, version pins will become standard. Renovate can then update dependencies.mcp too.
Near-term
Branch/SHA-pinned deps — update to latest commit on a branch. Lower-value but useful for internal packages.
Future
URL-based packages (microsoft/apm#692) — apm install https://...tar.gz with digest pinning. Would need a new Renovate datasource.
Future
.well-known skill discovery — HTTP-based skill distribution via /.well-known/agent-skills/index.json. Spec still draft v0.2.0.
